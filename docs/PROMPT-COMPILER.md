# Prompt Compiler Contract

The application should expose a very small intake while using the private Gauntlet Constitution server-side to generate a substantially richer execution prompt.

## User-facing intake

### 1. BUILD
What do you want to create?

### 2. BAR
What existing product, artifact, experience, outcome, or conceptual standard represents the level you want to meet or exceed?

### 3. ENVIRONMENT
Where/how should it be built? Examples: Codex, Claude Code, Base44, Lovable, Three.js, React, physical materials, a business process, etc.

### 4. SUCCESS
What must be true when the work is finished? Include hard constraints when known.

Optional attachments may include reference images, repositories, documents, datasets, screenshots, videos, specifications, or existing work.

## Compiler behavior

The server combines the intake with the private Constitution and creates a project-specific Master Gauntlet Prompt.

The compiler must infer rather than ask for information it can responsibly derive. It should identify:

- the true objective
- benchmark type and evidence quality
- constraint-recovery depth
- abstraction levels worth investigating
- specialist epistemic functions required
- recoverable vs arbitrary hidden information
- architecture/coordination contract
- decomposition strategy
- independent critics and evaluators
- benchmark tests
- resource budgets
- stop conditions
- feedback routes from construction to constraint intelligence

## Output principle

The generated prompt should tell the execution harness what to accomplish, how to establish ground truth, how to coordinate itself, how to evaluate itself independently, and when to stop — without dumping the private generic Constitution verbatim.

The compiler should produce a tailored operating specification, not a copy of the hidden source instructions.
